## I. 서론

### 1. 분석 배경 및 목적

이 프로젝트는 UCI Adult Census Income 데이터셋을 이용해 개인의 인구조사 정보(나이, 학력, 직업, 근무시간 등)로부터 연 소득이 `<=50K`인지 `>50K`인지를 예측하는 것을 목표로 한다. 단순히 모델 하나를 학습시키는 데 그치지 않고, 데이터 수집부터 정제, 두 라이브러리(Pandas·Polars) 비교, 자료형별 EDA, 통계 검정, 정적·인터랙티브 시각화, 모델 학습·평가·저장, 결과 보고서 자동 생성까지 **End-to-End 파이프라인**으로 구현하는 것이 이 실습의 핵심 목표다.

### 2. 분석 대상

인구조사 응답자 개인 단위 레코드이며, 원본 기준 32,561건이다. 각 레코드는 나이·고용형태·학력·결혼상태·직업·인종·성별·자본이득/손실·주당 근무시간·출신국가와 소득 구간(`income`)으로 구성된다.

| education | 최종 학력 |

## III. 데이터 수집 및 준비

### 1. Pandas·Polars 로드 비교

같은 원본 파일을 Pandas(`pd.read_csv`)와 Polars Lazy API(`pl.scan_csv → with_columns → filter → collect`) 양쪽으로 각각 읽어 다음 지표를 비교했다.

| 지표 | Pandas | Polars | 일치 여부 |
|---|---|---|---|
| 행 수 | 32,561 | 32,561 | 일치 |
| 열 수 | 15 | 15 | 일치 |
| workclass 결측 | 1,836 | 1,836 | 일치 |
| occupation 결측 | 1,843 | 1,843 | 일치 |
| native-country 결측 | 583 | 583 | 일치 |
| income `<=50K` | 24,720 | 24,720 | 일치 |
| income `>50K` | 7,841 | 7,841 | 일치 |
| 중복 제거 후 행 수 | 32,537 | 32,537 | 일치 |

실행 과정에서, 원본 파일의 쉼표 뒤 공백 때문에 Polars에서는 `fnlwgt`, `capital-gain` 같은 숫자형 컬럼이 문자열로 읽히는 문제가 실제로 발견되었다. Pandas는 `skipinitialspace=True`로 이 문제를 자동으로 처리하지만, Polars에는 같은 옵션이 없어 `str.strip_chars()`로 공백을 제거한 뒤 다시 정수형으로 casting하는 과정을 Lazy 파이프라인에 추가했다.

### 2. 결측치·중복·형식 정제

- 완전 중복 행 24건을 확인 후 제거했다 (32,561행 → 32,537행).
- 문자열 컬럼의 앞뒤 공백을 제거하고, `income` 값에 마침표가 붙어 있을 가능성까지 고려해 제거한 뒤 `<=50K` / `>50K` 두 범주로 통일했다.
- 숫자형으로 기대되는 컬럼(`age`, `fnlwgt`, `education-num`, `capital-gain`, `capital-loss`, `hours-per-week`)이 실제로 숫자형인지 점검했다.
- **결측치는 이 단계에서 대체(imputation)하지 않았다.** 형식만 정리한 이유와 실제 대체 시점은 부록 D에서 설명한다.

## V. 통계 분석

### 1. 상관분석 (Pearson, 숫자형 컬럼 · income 제외)

| 변수1 | 변수2 | 상관계수 |
|---|---|---|
| education-num | hours-per-week | 0.148 |
| education-num | capital-gain | 0.123 |
| education-num | capital-loss | 0.080 |

상관관계가 있다고 해서 인과관계가 있는 것은 아니다. 또한 `education`과 `education-num`은 같은 학력 정보를 다른 형태로 표현한 값이라 서로 상관이 높을 수 있어, 모델 feature로 함께 쓸 때 정보 중복에 유의해야 한다. 참고로 `income`을 `<=50K=0, >50K=1`로 임시 인코딩했을 때 `education-num`(0.335), `age`(0.234), `hours-per-week`(0.230)가 상대적으로 관련이 있어 보이나, 이는 단순 선형 상관 참고값일 뿐 공식 분석 결과가 아니다.

### 2. t-검정: income 그룹별 hours-per-week

| 항목 | 값 |
|---|---|
| H0 | 두 income 그룹의 평균 hours-per-week에는 차이가 없다 |
| H1 | 두 income 그룹의 평균 hours-per-week에는 차이가 있다 |
| `>50K` 그룹 | n=7,839, 평균 45.47 |
| `<=50K` 그룹 | n=24,698, 평균 38.84 |
| t 통계량 | 45.0950 |
| p-value | < 0.000001 |
| Cohen's d | 0.567 |

**검정 방법**: `scipy.stats.ttest_ind(..., equal_var=False)`로 두 그룹의 분산이 같다고 가정하지 않는 Welch t-test를 양측 검정으로 수행했다.

**결론**: p < 0.05이므로 귀무가설을 기각하며, 두 income 그룹의 평균 주당 근무시간에는 통계적으로 유의한 차이가 있다. 다만 표본 수가 매우 크면(32,537건) 실제로는 작은 차이도 매우 작은 p-value로 나타날 수 있으므로, 통계적 유의성만 볼 것이 아니라 평균 차이(6.63시간)와 효과 크기(Cohen's d 0.567, 중간 정도의 효과)를 함께 고려해야 한다.

### 3. 카이제곱 독립성 검정 (선택적 추가 분석)

| 조합 | chi2 | p-value | 판정 |
|---|---|---|---|
| education × income | 3593.21 | < 0.000001 | 유의한 연관성 있음 |
| occupation × income | 3672.96 | < 0.000001 | 유의한 연관성 있음 |
| sex × income | 1516.54 | < 0.000001 | 유의한 연관성 있음 |

세 조합 모두 기대빈도 5 미만인 셀이 없어 검정 결과를 신뢰할 수 있는 조건을 만족했다. p < 0.05이므로 세 조합 모두 income과 통계적으로 유의한 연관성이 있다고 판단했다.

## VI. 머신러닝 모델링

### 1. 문제 정의

- **target**: `income` (`<=50K` / `>50K`인 이진 분류)
- **feature**: `income`을 제외한 나머지 컬럼 중 수치형 6개, 범주형 8개
  - 수치형: `age`, `fnlwgt`, `education-num`, `capital-gain`, `capital-loss`, `hours-per-week`
  - 범주형: `workclass`, `education`, `marital-status`, `occupation`, `relationship`, `race`, `sex`, `native-country`
- `order_id`류 고유 식별자는 이 데이터셋에 없으며, `income`은 feature에서 제외해 데이터 누수를 방지했다.

### 2. 전처리 및 Pipeline 구성

| 구분 | 처리 |
|---|---|
| 수치형 | `SimpleImputer(strategy="median")` → `StandardScaler()` |
| 범주형 | `SimpleImputer(strategy="most_frequent")` → `OneHotEncoder(handle_unknown="ignore")` |
| 결합 | 위 두 전처리를 `ColumnTransformer`로 묶고, `LogisticRegression(class_weight="balanced")`와 함께 하나의 `sklearn.pipeline.Pipeline`으로 연결 |

**데이터 누수 방지**: 결측치 대체와 스케일링을 전체 데이터에 미리 적용하지 않고, `train_test_split(test_size=0.2, random_state=42, stratify=income)`으로 먼저 분리한 뒤 Pipeline이 train 데이터로만 전처리 규칙을 학습하도록 했다. seed는 `train_test_split`과 `LogisticRegression` 모두 `random_state=42`로 고정해 재실행해도 같은 결과가 나오게 했다.

### 3. 평가 결과

| 지표 | 값 |
|---|---|
| Accuracy | 0.8090 |
| Precision (`>50K` 기준) | 0.5684 |
| Recall (`>50K` 기준) | 0.8610 |
| F1-score (`>50K` 기준) | 0.6848 |
| ROC-AUC | 0.9099 |

**Confusion Matrix** (행/열 순서: `>50K`, `<=50K`)

|  | 예측 `>50K` | 예측 `<=50K` |
|---|---|---|
| 실제 `>50K` | 1,350 | 218 |
| 실제 `<=50K` | 1,025 | 3,915 |

income 클래스가 불균형(3.15배)하기 때문에 Accuracy만으로는 모델을 제대로 평가할 수 없다. `class_weight="balanced"`를 적용해 Recall(0.861)을 높인 대신 Precision(0.568)이 상대적으로 낮아졌는데, 이는 소수 클래스(`>50K`)를 더 적극적으로 찾아내는 쪽으로 모델이 조정되었다는 의미다.

### 4. 모델 저장 및 재로딩 검증

전처리와 모델이 모두 포함된 Pipeline 전체를 `joblib.dump()`로 `output/models/adult_income_pipeline.pkl`에 저장하고, `joblib.load()`로 다시 불러와 동일한 테스트 데이터를 예측했다. 저장 전/후 예측 결과가 정확히 일치함을 확인했다.

## VII. 결과 요약 및 인사이트

아래 내용은 이번 실행에서 나온 데이터 기반 결과이며, 인과관계로 확대 해석하지 않는다.

1. income 클래스는 `<=50K`가 다수(75.91%)를 차지하는 불균형 데이터이므로, Accuracy만으로 모델을 평가하면 소수 클래스(`>50K`)를 잘 못 맞혀도 점수가 높게 나올 수 있다.
2. `hours-per-week`는 income 그룹 간 통계적으로 유의한 차이를 보였으나(45.47 vs 38.84시간), 이는 관찰된 차이일 뿐 근무시간이 소득을 결정한다는 인과관계로 해석해서는 안 된다.
3. `education`, `occupation`, `sex` 모두 income과 통계적으로 유의한 연관성을 보였다.
4. `education`과 `education-num`은 같은 정보를 다른 형태로 표현하므로, 모델 feature로 함께 사용할 때 정보 중복(다중공선성)을 인지하고 있어야 한다.

## VIII. 윤리적 고려사항 및 한계

- 이 모델은 교육용 데이터 분석 실습 결과물이며, 교육 목적으로만 사용한다.
- 실제 채용, 대출, 보험, 복지 대상 선정 등 사람에게 실질적 영향을 주는 의사결정에 그대로 사용해서는 안 된다.
- Adult 데이터는 과거 시점의 인구조사 데이터이므로, 그 시절의 사회적 편향이 모델에 그대로 재현될 수 있다.
- Accuracy·F1 같은 지표가 높다고 해서 모델이 공정하다는 뜻은 아니다.
- `race`, `sex`, `native-country` 같은 민감 속성을 feature에서 제외하더라도 `education`, `occupation` 등 다른 변수가 민감 속성의 대리 변수(proxy) 역할을 해서 간접적으로 편향이 남을 수 있다.
- 이 모델은 인과관계를 설명하거나 개인의 능력·가치를 판단하는 모델이 아니라, 주어진 데이터에서 나타난 통계적 패턴을 학습한 결과일 뿐이다.


> 참고: 원래 계획한 구조에서는 통계 모듈 이름이 `statistics.py`였다. 그러나 `python src/main.py`처럼 스크립트를 직접 실행하면 `src/` 폴더가 `sys.path`의 맨 앞에 놓이는데, 이 상태에서 `statistics.py`라는 이름을 쓰면 파이썬 표준 라이브러리 `statistics` 모듈을 가려버려 seaborn 같은 라이브러리의 import가 깨지는 문제가 실제로 발생했다. 이름 충돌을 피하기 위해 `stats_analysis.py`로 변경했다.

## 부록 D. 결측치·통계 검정 방법론 요약

**결측치 처리**
- 수치형 컬럼: 이상치 영향을 덜 받는 중앙값(median)으로 대체
- 범주형 컬럼: 최빈값(most_frequent)으로 대체 (대안: 결측 자체가 의미 있다면 `Unknown` 범주로 별도 처리)
- 결측 행을 무조건 `dropna()`로 삭제하지 않고, 학습 데이터 보존을 위해 대체를 기본으로 선택
- 결측 원인(MCAR/MAR/MNAR)은 데이터만으로 단정할 수 없으므로 임의로 확정하지 않음
- 전체 데이터에 미리 대체값을 채우면 데이터 누수가 생길 수 있으므로, 실제 대체는 `sklearn Pipeline` 내부에서 train 데이터 기준으로만 수행

**통계 검정**
- t-test: `scipy.stats.ttest_ind(..., equal_var=False)` (Welch, 양측검정), 유의수준 0.05를 코드에서 직접 판단. p ≥ 0.05일 때도 "두 그룹이 같다"라고 단정하지 않고 "유의한 차이를 확인하지 못했다"라고 표현
- 카이제곱 검정: `pd.crosstab` + `scipy.stats.chi2_contingency`. 범주가 많은 컬럼은 상위 10개 외 나머지를 `Other`로 묶어 기대빈도가 너무 작아지는 문제를 완화
