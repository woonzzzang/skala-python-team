# 팀 개선사항 — 요구사항 체크리스트 반영 기록

과제 요구사항 체크리스트(항목 3, 4, 7, 8, 10, 17~43)를 하나씩 기존 코드와 대조해서,
**어떤 걸 고려했는지 → 무엇이 기준과 어긋났는지 → 어떻게 개선했는지** 순서로 정리했습니다.
이미 요구사항을 충족하고 있어 손대지 않은 항목도 "고려했지만 변경 없음"으로 남겨서,
빠뜨리고 안 본 게 아니라 확인하고 넘어갔다는 걸 팀원들이 알 수 있게 했습니다.

`팀_논의사항.md`가 "정답이 하나가 아니라 팀이 정해야 하는 선택"을 다룬다면,
이 문서는 "요구사항과 코드가 실제로 맞는지 대조하고 반영한 이력"을 다룹니다.

---

## 1. 모델 입력 재설계 — education과 education-num, 그리고 타깃 인코딩

**고려한 것**: education(범주형)과 education-num(수치형)을 모델에 둘 다 넣을지, 하나만 넣을지.
그리고 income 타깃을 EDA와 모델에서 같은 형태(문자열)로 쓸지, 다르게 쓸지.

**어긋난 점**:
- 요구사항은 "EDA에서는 education, 모델에서는 education-num"으로 역할을 나누라고 되어 있었는데,
  기존 코드는 모델 feature 리스트(`CATEGORICAL_FEATURES`)에 education이 그대로 포함돼 있어서
  education과 education-num이 **둘 다** 모델에 들어가고 있었습니다(정보 중복).
- 요구사항은 "EDA는 문자열, 모델의 y만 0·1로 변환"이라고 되어 있었는데, 실제로는 모델도
  문자열(`"<=50K"`/`">50K"`)을 그대로 `LogisticRegression.fit()`에 넣고 있었습니다.

**개선 내용**:
- `MODEL_CATEGORICAL_FEATURES`를 새로 만들어 `education`만 제외하고, 모델 feature는 이걸 쓰도록 분리
  (EDA·시각화는 기존 `CATEGORICAL_FEATURES`를 그대로 사용해 education 포함 유지)
- 모델의 `y`만 `(income == ">50K").astype(int)`로 0/1 매핑, EDA는 문자열 income을 그대로 유지
- 관련 파일: `main.py`, `modeling.py`, `visualization.py`

## 2. Pandas vs Polars 비교 범위

**고려한 것**: 요구사항에 있던 비교 항목 8개(shape, dtype, 결측치, 중복, income 카운트, groupby,
실행시간, 메모리) 중 어디까지 구현할지.

**어긋난 점**: shape·결측치·중복·income 카운트 비교만 있었고, dtype·groupby(추가)·실행시간·
메모리 비교는 없었습니다.

**개선 내용**: 팀 논의 결과 "실행시간"과 "메모리 사용량" 두 개만 추가하기로 결정
(dtype 비교, income 외 groupby 비교는 과하다고 판단해 범위에서 제외).
`memory_usage(deep=True)`(pandas) vs `estimated_size()`(polars), `time.perf_counter()`로 로딩 시간 측정.
관련 파일: `data_loader.py`, `main.py`

## 3. EDA 수치형 통계 — 있는지만 확인하던 것을 실제로 계산

**고려한 것**: 요구사항에 있던 8개 지표(기본 통계, IQR, 왜도/첨도, 결측 수·비율, 고유값 수,
0 비율, 이상치 후보 수, 소득 그룹별 평균·중앙값) 중 빠진 게 뭔지.

**어긋난 점**: IQR 값 자체, 결측 **비율**(수만 있었음), 고유값 수, 이상치 후보 수,
소득 그룹별 비교가 전부 빠져 있었습니다.

**개선 내용**: `perform_numeric_eda()`에 위 5개를 전부 추가했습니다. 이상치 후보는
Tukey's fence(`Q1 - 1.5×IQR` ~ `Q3 + 1.5×IQR`) 규칙으로 계산했고, 소득 그룹별 평균·중앙값은
전체 수치형 컬럼에 대해 별도 표로 출력하도록 했습니다. 관련 파일: `eda.py`

## 4. EDA 범주형 통계 — 결측 비율과 소득 교차 정보 추가

**고려한 것**: "단순 인원수"뿐 아니라 "그룹 내 고소득 비율"까지 같이 보여줄지.

**어긋난 점**: 결측 비율(%)이 없었고, 범주별 `>50K` 인원수·비율 같은 income 교차 정보가 전혀 없었습니다.

**개선 내용**: `perform_categorical_eda()`에 결측 비율과, 각 범주 줄마다
`>50K: N건 (X.X%)`를 함께 출력하도록 추가했습니다(income 컬럼 자기 자신을 순회할 때는 제외).
관련 파일: `eda.py`

## 5. 시각화 커버리지 — ROC Curve, 개별 분포, Plotly 5종

**고려한 것**: 요구사항에 명시된 시각화 종류(정적 9종, Plotly 6종)를 실제로 다 그리고 있는지.

**어긋난 점**:
- ROC Curve가 아예 없었습니다(AUC 숫자만 계산하고 곡선은 안 그림).
- capital-gain/capital-loss/hours-per-week는 개별 히스토그램 없이 income별 박스플롯으로만
  대체되어 있었습니다.
- Plotly는 산점도 1종만 있었고, 교육/직업별 비율 막대, facet 산점도, Treemap,
  Parallel Categories 5종이 빠져 있었습니다.

**개선 내용**:
- `create_roc_curve_plot()` 신설 (sklearn `roc_curve`/`auc` 사용)
- `create_additional_distribution_plot()` 신설 — 세 컬럼 개별 히스토그램 1×3 figure
- Plotly 5종 신설: `create_plotly_education_income_bar`, `create_plotly_occupation_income_bar`,
  `create_plotly_facet_scatter`, `create_plotly_treemap`, `create_plotly_parallel_categories`
- 관련 파일: `visualization.py`, `main.py`, `report.py`

## 6. 범주형 비율 차트의 계산 기준

**고려한 것**: 그래프에 인원수와 비율을 같이 보여줄지, 표본이 아주 적은 그룹(예: workclass의
`Never-worked` 7명)도 그대로 보여줄지.

**어긋난 점**: 요구사항은 "인원 수와 비율 모두 표시", "표본 수가 적은 그룹 제외"를 요구했는데,
기존 차트는 비율(%)만 막대로 보여주고 표본 크기와 무관하게 모든 범주를 다 그리고 있었습니다.

**개선 내용**: `create_categorical_eda_plot()`에서 각 막대 구간에 `N건 (X.X%)`를 함께
표시하도록 하고, 표본 30건 미만 그룹은 차트에서 제외하되 어떤 그룹을 왜 제외했는지
콘솔에 로그를 남기도록 했습니다(조용히 빠뜨리지 않기 위함). 관련 파일: `visualization.py`

## 7. 상관분석 — Pearson 외 참고 지표 추가

**고려한 것**: 수업 기준(Pearson)을 그대로 공식 결과로 쓰되, Spearman/Kendall을 참고용으로
같이 보여줄지.

**개선 내용**: Pearson은 그대로 공식 분석 기준으로 유지하고, Spearman·Kendall을 추가로 계산해서
Pearson과의 최대 차이를 출력하도록 했습니다. 차이가 크면 "선형이 아닌 단조 관계가 있을 수 있다"는
참고 신호로만 쓰고, 결론은 Pearson 기준으로 유지합니다. 관련 파일: `stats_analysis.py`

## 8. t-test — 주제 확장과 "어떤 검정을 쓸지" 자동 판단

**고려한 것**: 요구사항은 t-test 주제 5개(소득×hours-per-week, 소득×age, 성별×hours-per-week,
workclass 두 그룹×hours-per-week, 소득×education-num)와, 검정 종류를 정규성/등분산성 확인 후
선택하라고 되어 있었습니다.

**어긋난 점**: 실제로 실행되는 t-test는 소득×hours-per-week 1개뿐이었고, Welch t-test로
고정돼 있었습니다. 정규성·등분산성을 먼저 확인하는 절차도 없었습니다.

**개선 내용**: `perform_two_group_test()`를 새로 만들어서, 비교 전에 Shapiro-Wilk(정규성)와
Levene(등분산성)을 먼저 계산하고 그 결과에 따라 **Student t-test / Welch t-test / Mann-Whitney U**
중 하나를 자동으로 고르도록 했습니다. 나머지 4개 주제도 이 함수로 실행하도록 `main.py`에 추가했습니다.
실제로 돌려보니 표본이 워낙 커서(수천~수만 건) 정규성 검정이 거의 다 기각돼, 4개 주제 모두
Mann-Whitney U가 자동으로 선택됐습니다. 대응표본 t-test는 이 데이터셋에 반복측정이 없어서
적용 대상이 아니라는 점도 코드 주석으로 남겼습니다. 관련 파일: `stats_analysis.py`, `main.py`

## 9. 카이제곱 검정 — 대상 컬럼 확장

**고려한 것**: education×income, workclass×income 둘 중 하나 또는 인사이트 있는 조합이면
된다는 요구사항 문구.

**개선 내용**: 기존 3종(education, occupation, sex × income)에 workclass, marital-status,
race, native-country를 추가해 7종으로 늘렸습니다. workclass는 표본이 매우 작은 범주
(`Without-pay`, `Never-worked`)가 있어 기대빈도 5 미만 셀이 생기는데, 이건 억지로 없애지 않고
"신뢰도가 다소 낮을 수 있다"고 결과에 그대로 표시하도록 했습니다. 관련 파일: `stats_analysis.py`, `main.py`

## 10. 모델 비교 — LogisticRegression 단독에서 RandomForest 비교로

**고려한 것**: `팀_논의사항.md` 7번 항목에서 이미 "시간 되면 RandomForest도 비교해보자"고
논의됐던 부분입니다.

**개선 내용**: `build_candidate_pipelines()`로 LogisticRegression과 RandomForest를 각각 학습·평가하고,
`select_final_model()`로 F1-score를 우선 기준 삼되 차이가 0.01 이내면 해석 가능성이 더 좋은
LogisticRegression을 최종 선택하는 로직을 추가했습니다.

실제 실행 결과:

| 지표 | LogisticRegression | RandomForest |
|---|---|---|
| Accuracy | 0.8085 | 0.8637 |
| Precision | 0.5678 | 0.7593 |
| Recall | 0.8603 | 0.6358 |
| F1-score | 0.6841 | 0.6921 |
| ROC-AUC | 0.9095 | 0.9101 |

F1 차이가 0.008로 허용 범위(0.01) 안이라 LogisticRegression이 최종 선택됐습니다.
RandomForest는 Precision은 높지만 Recall이 낮아 `>50K`를 더 많이 놓치는 경향이 있다는 점도
같이 확인했습니다. 관련 파일: `modeling.py`, `main.py`

## 12. 실제 실행 중 발견한 버그 (요구사항과 무관하지만 같이 고침)

체크리스트 반영을 검증하려고 가상환경을 새로 만들어 `python src/main.py`를 처음부터 끝까지
돌려봤고, `py_compile`만으로는 안 잡히는 런타임 버그 2개를 발견해서 같이 고쳤습니다.

1. **Python 3.9 호환성**: `float | None` 같은 최신 타입 힌트 문법이 실행 환경(Python 3.9)에서
   함수 정의 시점에 바로 평가되면서 `TypeError`가 났습니다.
   → `data_loader.py`, `modeling.py`에 `from __future__ import annotations` 추가로 해결.
2. **범주형 차트 정렬 오류**: `Index.map().sort_values().index` 체이닝에서
   `AttributeError`가 발생했습니다. → `group_sizes.loc[...].sort_values().index` 형태로 수정.

## 변경하지 않은 항목 (이미 요구사항 충족 확인)

아래 항목들은 기존 코드가 요구사항과 이미 일치해서 손대지 않았습니다.

- 컬럼명 하이픈 표기 통일, `?` 결측값 인식(na_values="?" / null_values="?")
- 결측 있는 셀만 최빈값/중앙값으로 대체(`SimpleImputer`가 원래 그렇게 동작함)
- 완전 중복 행 `drop_duplicates()` 제거
- 민감 변수(race, sex) 모델 포함, 희소 범주 병합 없이 전부 유지
- 양측 검정, 유의수준 0.05, p-value 해석 문구, Cohen's d 함께 해석
- train/test 80:20 + stratify + random_state=42, LogisticRegression 기본 모델,
  class_weight="balanced", StandardScaler
- Accuracy/Precision/Recall/F1/ROC-AUC/Confusion Matrix 전부 사용

## 보류된 항목

- **결측치 처리 시점을 EDA 단계로 옮기는 안**: 논의는 했지만, train/test 분리 전에 전체 데이터로
  최빈값/중앙값을 계산하면 test 정보가 새는 data leakage가 생기기 때문에 지금처럼 모델링
  Pipeline 내부(학습 시점)에서 처리하는 걸 유지하기로 했습니다. 요구사항 문구가 "EDA 단계 수행"을
  꼭 의미하는 거라면 팀에서 다시 논의가 필요합니다.
